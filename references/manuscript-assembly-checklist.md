# 论文章节组装检查清单手册（Manuscript Assembly Checklist）

> 子技能 `paper-assembly` 给了"IMRaD 结构、论证链、段落衔接"，但没把**每章该过哪些硬检查、论证链怎么逐条验证、全文一致性怎么扫**量化成可勾选清单。本篇把组装从"写完就行"变成可审计的验收单。

## 1. IMRaD 验收矩阵

| 章节 | 必过检查 | 失败信号 |
|------|----------|----------|
| Introduction | 痛点→空白→贡献三段清晰；贡献点可数（3 条左右） | 贡献写成"本文研究了…"（无具体增量） |
| Methods | 可复现：数据/参数/环境齐全；伦理声明（如适用） | 别人按写无法复现 |
| Results | 只报发现不解释；图表编号与正文引用对应 | 结果与讨论混写 |
| Discussion | 回答引言问题；关联已有工作；讲局限性 | 重复结果、无局限 |
| Conclusion | 一句话核心贡献 + 未来方向 | 又展开新结果 |

## 2. 论证链验证（逐条）

每条主张必须有：`主张 → 证据 → 推理` 三件套。逐段扫描：

```
for 每段:
  提取主题句（主张）
  是否存在支撑证据（数据/引用/实验）？
  推理是否显式连接主张与证据？
  无证据的主张 → 标记 [unsupported]
```

> 反模式：满是"显然""众所周知"却无引用的主张——审稿人最反感。

## 3. 全文一致性扫描

| 维度 | 检查 | 工具 |
|------|------|------|
| 术语 | 同一概念全篇同名 | 人工 / grep 候选异名 |
| 时态 | 已完成用过去时，普遍结论用现在时 | 人工 |
| 图表引用 | 每图每表被正文引用且编号连续 | grep `Figure/Table \d` |
| 缩写 | 首次出现写全称 | 人工 |
| 文献 | 正文 `\cite` 全部在 .bib | 见 `reference-management-playbook.md` |

## 4. 可执行的辅助命令

```bash
# 检查 Figure/Table 引用是否连续且无遗漏
grep -oE 'Figure [0-9]+|Table [0-9]+' manuscript.tex | sort -u

# 检查未定义的 \cite 键（需配合 .bib）
# 见 academic-citation 子技能的交叉比对流程
```

## 5. 典型坑与规避

| 坑 | 表现 | 规避 |
|----|------|------|
| 贡献不具体 | "本文研究了X" | 写清 3 条增量 |
| 主张无证据 | "显然…" | 每条主张配证据 |
| 结果混讨论 | 结果里解释意义 | 结果只报，讨论再解 |
| 图表漏引用 | 图存在但正文没提 | 每图每表被引用 |
| 术语漂移 | 同物异名 | 全文统一术语 |
| 时态乱 | 过去/现在混 | 已完成过去时、普适现在时 |

## 6. 段落衔接句式库

- **递进**：`进一步看 / 在此基础上 / 更重要的是`
- **对比**：`与之相反 / 相比之下 / 然而`
- **因果**：`因此 / 这导致 / 由此推断`
- **收束**：`综上 / 简言之 / 本节的结论是`

> 每章结尾用一句"本节结论"承接下章开头，避免章节间断裂感。

## 7. 图表与投稿终检

- **图表自审**：每图每表有编号、有标题、被正文引用、分辨率 ≥300dpi、矢量优先。
- **投稿前终检**：摘要≤期刊字数、关键词 3-6、参考文献格式统一、匿名稿隐去身份。
- **拒稿后重构**：先读审稿意见聚类（方法/贡献/表达），针对性改，改点逐条回复。

## 8. 实战：一篇 8 页会议论文的组装验收

章节与验收：
```
Introduction（1p）: 痛点→空白→3 条贡献（具体：S1 剪枝、S2 量化、S3 蒸馏）
Methods（1.5p）: 可复现，超参表 + 环境（GPU/框架/随机种子）
Results（2p）: 只报；Figure1-4 编号连续且正文全引用
Discussion（2p）: 回扣 3 贡献；对比 SOTA；局限：仅在 ViT 验证
Conclusion（0.5p）: 一句话贡献 + 未来：扩到 LLM
```
论证链扫描：每条主张（如"S1 在精度损失<1% 下提速 2.3×"）均有表格/图证据，无 [unsupported]。
一致性：术语"compression ratio" 全篇统一；时态：已完成过去时；Figure 编号连续。

## 9. 组装反模式（扩展）

| 反模式 | 后果 | 修正 |
|--------|------|------|
| 贡献不具体 | 无增量 | 写清 3 条 |
| 主张无证据 | 被质疑 | 每条配证据 |
| 结果混讨论 | 混乱 | 结果只报 |
| 图表漏引用 | 图孤立 | 每图被引 |
| 术语漂移 | 同物异名 | 全篇统一 |
| 时态乱 | 不专业 | 过去/现在分 |
| 缺局限 | 不严谨 | 明说边界 |
| 缩写无全称 | 费解 | 首次写全 |
| 结论新结果 | 违规 | 只总结 |
| 引用缺失 | 被质疑 | 正文↔.bib 比对 |

## 10. 投稿信与回复模板

Cover letter 要点（≤1 段）：
```
We submit "X" for <venue>. It contributes: (1) S1 (2) S2 (3) S3.
Prior work lacked <gap>; our method achieves <result> on <bench>.
```
审稿意见回复（逐条）：
```
R1: <意见摘要>
A: We added <experiment> (§3.2); result shows <x>, confirming <y>.
```
态度：感谢 + 具体改动 + 位置引用，不空泛"we addressed"。

## 11. 组装检查清单

- [ ] Introduction：痛点→空白→可数贡献
- [ ] Methods：可复现，参数/数据/环境齐全
- [ ] Results：只报发现，图表编号与正文对应
- [ ] Discussion：回扣引言、关联文献、含局限性
- [ ] Conclusion：一句话贡献 + 未来方向
- [ ] 每条主张有证据与推理（无 [unsupported]）
- [ ] 术语/时态/缩写全文一致
- [ ] 所有 `\cite` 在 .bib 中有对应且字段完整

## 12. 章节衔接与过渡设计

好论文不是各章拼起来，而是章章咬合。过渡设计：

- **章首回扣**：每章开头一句话承接上章结论，如"上一节表明 X 不足，本节提出 Y"。
- **章尾预告**：每章结尾一句指向下章，如"下一节在 Z 数据集上验证 Y"。
- **跨章术语锁**：同一概念全篇同一词，避免"模型/方法/框架"混用造成读者混淆。
- **图表桥接**：图注点明"图 3 印证了第 2 节的假设 H2"，让图不孤立、不重复正文。

## 13. 论证链实战示例

以"方法章"一条主张为例，演示 `主张→证据→推理` 三件套怎么写：

```
主张: S1 剪枝在精度损失 <1% 下提速 2.3×。
证据: 表 2（ImageNet 上 Top-1 从 76.4% 降到 75.8%，推理 18ms→7.8ms）。
推理: 损失 <1% 在统计波动内（见 §4.3 置信区间），而延迟降 57%，故性价比成立。
```

反例（无证据）：
```
"显然剪枝能大幅加速模型。"   ← 无数据、无引用，审稿人直接标 [unsupported]
```

## 14. 投稿前终检清单（扩展）

- [ ] 摘要 ≤ 期刊字数、含研究问题/方法/结果/结论四要素
- [ ] 关键词 3-6 个，与正文高频词一致
- [ ] 参考文献格式统一（期刊指定样式），无遗漏无多列
- [ ] 匿名稿隐去作者/致谢/项目编号，元数据也清
- [ ] 图表分辨率 ≥300dpi，矢量优先，编号连续
- [ ] 正文 `\cite` 全部在 .bib 且有对应条目（跑交叉比对）
- [ ] 字数/页数符合期刊 limits
- [ ] 附 Cover letter 与高亮要点（highlight）
- [ ] 已逐段扫论证链，无 [unsupported] 主张

## 15. 拒稿重构的实战流程

被拒不是终点，是下一版的输入：

1. **意见聚类**：把审稿意见按主题聚类（方法/贡献/表达/实验），不是逐条孤立看。
2. **区分必改与可争**：方法缺陷必改；表达方式可争，用证据礼貌反驳。
3. **改点对齐**：每条意见对应一个改动，并在 response 里标"见 §X.Y 第 Z 段"，便于审稿人定位。
4. **重投策略**：改透后投同级或下一级期刊；若只小改，回原刊需说明已逐条处理。
5. **保留版本**：留被拒版与修改版 diff，方便追踪改了什么、为何改。

> 拒稿回复的铁律：**感谢 + 具体改动 + 位置引用**，不写空泛的"we addressed the reviewer's concern"。审稿人看的是你有没有真的改，不是态度好不好。
